## D-61 — Las pantallas del prototipo son una referencia: Claude Code las corrige y completa para que el caso de uso funcione

- Fecha: 21/11/2026
- Decidió: el estudiante (pedido del 21/11/2026, al validar el lote C2 de «Comercial 1»); redacción de Claude.
- Antes:
  - L7 de `CLAUDE.md` dice que el prototipo es «solo una guía visual» y que, si su lógica difiere del caso de uso, manda el caso de uso.
    Pero no dice qué hacer cuando a la pantalla **le falta** algo que el caso de uso necesita (un campo, un botón, un estado, un mensaje, un
    paso), o cuando lo que tiene **está mal** como interfaz (un flujo que no cierra, un control que no sirve para el dato, un caso vacío sin
    resolver).
  - L9 dice que, si falta algo, Claude Code frena y no lo inventa. Leído al pie de la letra, una pantalla incompleta frenaría cada tarea.
  - Los extractos de cada ronda ya listan las diferencias detectadas («Lo que difiere del prototipo»), pero ninguna revisión las encuentra
    todas.
- Decisión:
  1. **El prototipo es una referencia de estructura, contenido y estilo (D-47), no una especificación.** Puede tener errores y le pueden
     faltar elementos.
  2. **Claude Code corrige y completa la pantalla sin frenar**, con su criterio de diseñador de interfaces, cuando hace falta para que el caso
     de uso se pueda concretar o para que la pantalla funcione bien. Por ejemplo:
     - agregar el campo, el botón, la columna, el filtro o el paso que el caso de uso pide y la pantalla no tiene;
     - el estado vacío, el de error, el de carga y el de «sin permiso» que la pantalla no muestra;
     - una ventana de confirmación o de resumen que el caso de uso pide;
     - cambiar un control que no sirve para el dato (un desplegable para una lista que crece, por ejemplo) o un flujo que no cierra;
     - los textos de ayuda, de error y de confirmación que falten, con el tono de `.claude/rules/interfaz.md`;
     - lo que haga falta para la accesibilidad, el teclado, el celular y el funcionamiento sin JavaScript.
  3. **El límite: la pantalla se corrige con lo que ya dicen las fuentes de más peso.** Claude Code **frena y pregunta** (L7, L9) si la
     corrección necesita:
     - una regla de negocio, un permiso o un cálculo que no está en el caso de uso, el modelo o una decisión;
     - un atributo nuevo del modelo (una columna) que no está en el extracto;
     - contradecir el caso de uso, el modelo, una decisión o el código mergeado.
     Un texto que falta **no** es un motivo para frenar (punto 2); una regla que falta, sí.
  4. **Todo se informa.** Cada corrección o agregado va al «Cierre» de la tarea, en una lista «Pantallas: lo que se corrigió del
     prototipo», con qué tenía la pantalla, qué se hizo y por qué (el paso o la regla del caso de uso). El estudiante lo revisa a mano.
  5. Lo de los puntos 2 y 3 vale también para las diferencias que **sí** están listadas en un extracto: la lista es lo que ya se detectó, no
     todo lo que hay.
- Por qué:
  - El prototipo se hizo para mostrar el sistema, no para especificar cada estado de cada pantalla; esperar a que la documentación cubra
    cada detalle visual frena las tareas sin mejorar el resultado.
  - El límite del punto 3 conserva lo que protegen L7 y L9: que el comportamiento del sistema salga de los casos de uso y del modelo, y no
    de una deducción del código o de la pantalla.
- Fuentes: pedido del estudiante del 21/11/2026; L7 y L9 de `CLAUDE.md`; D-44 (documentación completa por ronda); D-47 (estilo del
  prototipo de producción).
